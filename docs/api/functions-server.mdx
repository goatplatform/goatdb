# Server Functions

## compile

**<code>compile(options: [CompileOptions](/api/types/compileoptions)): Promise&lt;void&gt;</code>**

Compiles a GoatDB application into a standalone executable.

This function performs the following steps:
1. Bundles client-side code (JS/TS/TSX) into a single JavaScript file
2. Processes static assets (HTML, CSS, images, etc.)
3. Generates build information
4. Compiles the server entry point into a native executable for the target
   platform

## startDebugServer

**<code>startDebugServer(options: [DebugServerOptions](/api/types/debugserveroptions)&lt;US&gt;): Promise&lt;void&gt;</code>**

Starts a local debug server. The debug server implements live reload and
automatically transpiles TypeScript and JSX using ESBuild on both Deno and
Node.js. By default it opens the local URL in a browser, but embedded callers
can disable that with `openBrowser: false`. `onReady` runs after HTTP listening
begins, receives `{ server, url, stop }`, and `url` is the server origin
(`scheme://host:port`) chosen for that run. `stop()` is safe to call more than
once. The promise resolves after clean shutdown and rejects if startup fails or
the live watcher fails after startup. Only one active debug server instance is
supported at a time. Runtime config discovery is runtime-specific: Deno uses
`deno.json`, Node.js uses `package.json`.

> **Breaking change:** `startDebugServer` previously returned `Promise<never>`;
> it now returns `Promise<void>`, resolves after clean shutdown, and rejects on
> startup failure or terminal watcher failure. Code that relied on the `never`
> return type for control-flow narrowing will need updating. `config.debug` is
> now saved on entry and restored on exit, so the global debug flag is no
> longer leaked after the server stops. Additionally, config file
> auto-detection is now runtime-specific: Deno requires `deno.json` and Node.js
> requires `package.json` (no cross-runtime fallback). Deno projects that
> previously relied on automatic `package.json` detection must either add a
> `deno.json` or pass `denoJson` explicitly.
